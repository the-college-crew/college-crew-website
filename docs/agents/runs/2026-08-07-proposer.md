## Candidates generated and killed (5)

1. **Platform-wide "jobs completed" / aggregate rating stat on the homepage**
   (Track A) — killed on the merits, not just process. Checked
   `getProviderCompletedJobCounts` in `lib/db/queries.ts` — it's per-provider,
   nothing platform-wide is computed or shown. Built a quick estimate of what
   an honest number would look like at 6 providers this early in a pilot,
   and concluded a small raw count exposed prominently on the homepage
   (every visitor sees it, not just people already evaluating one provider)
   risks reading as a red flag rather than a trust signal — the opposite of
   CC-006's per-review badge, which only ever appears next to an actual
   review and so has no ugly floor. A homepage counter has no such graceful
   scaling at low volume.
2. **Rate limiting on other server actions** (`submitSupportTicket`, review/
   dispute submission), matching the DB-native quota pattern the new AI
   support endpoint uses (`reserve_ai_support_request` RPC) (Track B) —
   killed. Confirmed `submitSupportTicket` already has a honeypot field for
   spam, so this isn't an unconsidered gap — extending real rate limiting to
   more actions means a new migration (request-log table + RPC), a schema
   change, explicitly out of scope for a same-day `S` item and the kind of
   thing that touches the shared production database.
3. **Dynamic per-page Open Graph images** (`opengraph-image.tsx` via
   `ImageResponse`) as a follow-up to CC-010 (Track B) — killed. Too close to
   CC-010, which is still an open PR (#231) awaiting Zach's merge — proposing
   a bigger version of the same idea in the same window it's pending review
   reads as padding rather than a distinct finding. Let it land and be
   assessed first.
4. **AI support widget accessibility/safety review** (Track B/A) — killed.
   Read through `feedback-launcher.tsx` and `app/api/support/assistant/
   route.ts` expecting to find the kind of gap CC-007 found in `FieldError`.
   Instead found: auth gating, a DB-native rate-limit quota with a
   `Retry-After` header, a 20s upstream timeout with abort handling on
   client disconnect, deliberately vague error messages with correlated
   server-side logging, an `aria-live` announcement region, and focus
   management on open/close already in place. No concrete gap found without
   a much deeper investigation that would risk duplicating the feature's own
   very recent plan (`docs/plans/2026-08-06-ai-support-widget.md`).
5. **Provider onboarding friction reduction** (earlier payout setup,
   reduced verification friction) (Track A) — killed. Research named payout-
   method setup delay as the single biggest onboarding drop-off cause in gig
   marketplaces — but the team already acted on exactly this: "Move Stripe
   into provider onboarding" landed 2026-08-05. No remaining gap found
   without actual funnel data, which isn't available in this sandbox.

No candidate survived. Per the prompt's own instruction — say so rather than
