*CC-008 — Add baseline HTTP security headers (no CSP yet)* (S)
`next.config.ts` ships zero HTTP security headers — no headers() export, no middleware.ts either — on the app that collects login credentials, driver's-license photos, and live Stripe payments. Add X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin, X-Frame-Options: DENY, and a conservative Permissions-Policy via next.config.ts's headers(). All four are the "safe pack" 2026 guidance recommends without caveats — none of them restrict which scripts/styles/connections load, so there's no risk to Stripe Elements, Supabase Realtime, or the new Google OAuth flow.
_Why this one:_ verified-zero gap, one function, one file, zero interaction risk. A full CSP is the more complete fix but current guidance says to run it in report-only mode for 2–4 weeks before enforcing — real ongoing work, and getting it wrong risks silently breaking the live Stripe checkout. This deliberately stops short of that.
_Devil's advocate:_ 6 providers isn't a realistic attack target yet — true, but the fix is one function with no ongoing cost, so there's no reason to wait for an incident.

*CC-009 — Add a "Payments secured by Stripe" line next to the pay button* (S)
The confirm page already surfaces the cancellation policy next to the pay panel (CC-003) but says nothing about payment security at the moment a customer hands over a card number — Stripe is the real, live integration (lib/stripe/), the page just never says so. _Why this one:_ same shape as CC-003/CC-006 — surfaces a true existing fact at the exact point research says it matters most.
_Devil's advocate:_ "Stripe" may mean nothing to some customers — true, but it costs one copy key and reads as more credible than nothing.
